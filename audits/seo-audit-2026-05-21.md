# SEO Audit: analytics.seokru.com — 2026-05-21

**Verdict: SHOULD BE NOINDEX + BEHIND LOGIN. Currently publicly crawlable but designed as internal SaaS tool.**

---

## Indexability Score: 3/10

### Top 3 Findings

1. **Critical: Missing Mobile Viewport Tag**
   - Landing page lacks `<meta name="viewport">` → fails mobile-first indexing.
   - Impacts Core Web Vitals (INP, CLS) and mobile ranking signals.
   - Add: `<meta name="viewport" content="width=initial-scale=1.0">` to `landing.blade.php` line 5.

2. **High: Login Wall Not Enforced for Crawlers**
   - Landing page publicly accessible (HTTP 200) with "Connect Google" CTA.
   - Routes like `/dashboard`, `/ask`, `/r/{report}` require auth but return redirect, not 401/403.
   - Crawlers can index the landing page (currently 16.4 KB of mostly CSS).
   - Recommendation: Add `<meta name="robots" content="noindex, nofollow">` OR require login on landing via middleware.

3. **Medium: No Sitemap or Structured Data**
   - `/sitemap.xml` returns 404.
   - No Organization/Website schema markup (JSON-LD).
   - No canonical tag on landing page.
   - Since this is SaaS (reports behind login), sitemap unnecessary—but schema would help brand signals for `/privacy`, `/terms`, `/about`.

## Recommendation

**Option A (Recommended): Full Noindex + Login Middleware**
```php
// In landing.blade.php <head>
<meta name="robots" content="noindex, nofollow">

// In ReportController or middleware
public function __construct() {
    $this->middleware('auth')->except(['landing', 'authGoogle', 'authCallback']);
}
```

**Option B: Keep Public Landing (Brand/SEO Play)**
- If you plan public marketing landing page:
  - Add viewport tag
  - Add `og:image` (1200x630px, hero screenshot)
  - Add JSON-LD Organization schema
  - Create `/llms.txt` with opt-in for AI citations
  - Block crawlers from `/dashboard`, `/ask`, `/r/*` via robots.txt

**Current State:** Hybrid vulnerability—landing is public SEO, but its purpose (drive OAuth login) means nothing valuable is crawlable beyond "connect now."

## CWV + Performance Notes

- **LCP:** Depends on hero image size + render-blocking CSS. Inline CSS is good; move `<link rel="*">` to async if possible.
- **INP:** No visible JS bloat on landing page detected. Be cautious with chart rendering after login.
- **CLS:** No width/height on any images; will shift on load. Set explicit dimensions on favicons + og:image.
